# 改片和交付

目录：改片循环 · 找到真正的错 · 常见的真正的错 · 确认小样 · 整片和交付 · REVIEW.md

## 改片循环

1. 用户看了成片或小样，按时间点提问题。比如"1:05–1:06 过程有错，你自己看看""这里的树只有半截""人坐下的时候脚不见了"。
2. **先自己找到真正的错**（下一节）。用户说的往往只是表面，真正的错常常有两三处。动手之前，先把"实际的错"一条条讲清楚。
3. 修。只动有问题的地方，别的镜头不要顺手改。
4. **只渲受影响的片段**，每段前后各多留 1–2 秒：`npx -y hyperframes@0.9.41 render --start=62.5 --end=70.5 --fps=30 --max-bitrate=16M --quiet -o renders/_fix/seg-b.mp4`。动态的问题（闪烁、突然出现、过程不连贯）一定要看连续的帧，不能只看一张截图。
5. 用 `review_clip.py` 拼成一条**确认小样**：带标题卡，720p，配原曲，小于 30 MB，手机能收。告诉用户每一条改了什么、怎么确认的。
6. 用户可能接着提新的问题，那就回到第 2 步。
   - 注意：小样里的时间不是成片里的时间。小样每段前面有 1.2 秒标题卡，片段又是从成片某一秒开始截的，要换算回成片的时间再去找。
7. 用户说"重渲整片"，再渲整片，然后跑 `check_render.py` 和 `deliver.sh`。
8. 在 `REVIEW.md` 里补一行：时间、用户说的、实际的错、改法。

## 找到真正的错

- 用户说的时间点，先粗看，再细看：
  - `contact.py renders/_master.mp4 63 69 0.25 renders/_notes/a.jpg`（每 0.25 秒一格）
  - 有问题的那一两秒逐帧看：`contact.py … 65 66 0.0333 …`
- 不必先渲视频：直接用 snapshot 截源码里的那一刻（`--at 65.2,65.35,…`）。
- 用 Read 看接触表时，挨个问自己：
  - 动作连贯吗？人物有没有突然出现、消失或瞬移？
  - 表情和上一镜的情绪接得上吗？
  - 天色、时间和歌词一致吗？
  - 歌词有没有压在脸上？
  - 底边、侧边有没有露出黑边或底色？
  - 东西有没有被图层的边切掉？
- 改完回归一遍：同一段再截一次，对比改前改后。

## 常见的真正的错

| 用户说的 | 实际的错（常见原因） | 改法 |
|---|---|---|
| "这里像白天" | 回忆段落用了暖黄天空，但没有太阳，也没有暗下来；前后两镜都是夜里，歌词也在夜里 | 时间跟歌词走：改成同一个夜里，暖色只留给一扇亮着的窗 |
| "这段过程有错" | 几处一起错：人物像被拖着平移；歌词压在脸上；底边露黑边；下一镜人物不见了，或者表情像什么都没发生 | 一拍只拍一个清楚的动作；表情接上上一镜的情绪；补满背景；人物的去向要交代 |
| "人物突然出现" | 上一镜只拍天空，下一镜人物突然冒出来，还马上出事 | 合成一个连贯的镜头，或者让人物在上一镜就已经在画面里；出事之前留 1 秒以上的铺垫 |
| "脚不见了" | 角色先画在离屏画布上，画布下边只到站着时的鞋底，坐下后小腿超出画布被切平 | 把角色画布（`BOX`）往外扩，包住所有姿势 |
| "树只有半截" | 树画在一张起点太低的图层上，树冠上半截超出图层被切平；每个圆圈都描边，看着乱 | 图层范围包住树冠；只描最外一圈轮廓 |
| "这一秒在闪" | 平躺的剪纸和地面在同一个平面上抢显示（z-fighting） | 平躺时稍微抬高，每层错开一点；渲那一小段看连续 12 帧确认 |
| "手太长、看着诡异" | 手臂画成了长管子，手肘折成硬角 | 手臂缩短，伸出去的手和垂下的手一样长；手肘用圆弧 |
| "背影像鬼" | 长发角色的背影把整个身子盖住了 | 不画背影，转身用镜像 |

## 确认小样

```bash
.venv/bin/python -I <skill>/scripts/review_clip.py "renders/修改確認-1.mp4" \
  renders/_fix/seg-a.mp4 40   "0:42" "天色改成夜里" \
  renders/_fix/seg-b.mp4 62.5 "1:05–1:06" "动作接上上一镜" \
  renders/_fix/seg-c.mp4 81   "1:23" "树冠补全"
```

- 标题卡：深蓝底，黄色大标题写时间点，白色副标题写改了什么。繁体还是简体跟着用户。
- 每段的声音从原曲里截，起点是"这一段在成片里的开始秒"，所以画面和歌对得上。

## 整片和交付

```bash
npx -y hyperframes@0.9.41 render --fps=30 --max-bitrate=16M --quiet -o renders/_master.mp4     # 放后台跑
.venv/bin/python -I <skill>/scripts/check_render.py renders/_master.mp4 --boxes data/lyric_boxes.json --pairs
bash <skill>/scripts/deliver.sh renders/_master.mp4 assets/song.wav "<成片>.mp4" ["<预览-720p>.mp4"]
```

交付前确认这几项：

- **帧数**：等于片长 × 30。`--pairs` 报出来的重复帧，应该只有切点后缓入的第一帧（2 分钟约 3600 帧，正常只有几对）。
- **画面**：没有静止段；切点和分镜表一致（颜色相近的两镜可能漏报，要逐帧看）；每句开唱后 0.3 秒，字已经出来并开始刷色。
- **响度**：成片和原曲差不到 0.2 LU。渲染器自带的音轨会低约 0.6 LU，`deliver.sh` 已经换回原曲。
- 发给用户时说清楚：哪些查过了，哪些只看过、没有测。比如声音只量了，没法"听"；歌词刷色只核对了每句的开头。

## REVIEW.md

写在项目根目录，下次改片前先读它。结构：

```markdown
# 成片自查（<片名> <画风>版）
> 成片路径、规格（1080p、30 fps、时长、原曲音轨）；检查脚本；总览图
## 我做的创作决定      （学了参考片的什么、没学什么；和原分镜不一样的地方）
## 测了什么            （表格：静止段 / 切点 / 歌词 / 帧率 / 响度，每项写结果）
## 只看了、没测的
## 第 N 轮：按用户的时间点修的   （表格：时间 | 用户说的 | 实际的错 | 改法）
## 最弱的镜头          （自己觉得还能更好的地方，以及怎么改）
## 保留的警告          （比如 font_face_local_only，以及什么情况下要处理）
```
