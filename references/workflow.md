# 六步流程详解

流程骨架来自 Winhao 的教程（Opus 5.5 + HyperFrames，六步做一支 MV）。下面是实际做片时跑通过的做法，以及每一步的提示词卡。卡片按教程的 `<role>/<task>/<avoid>/<check>` 结构改写过，可以直接给自己或子任务用。

目录：0 准备 · 1 理解音乐 · 2 定画风 · 3 画角色 · 4 剧本和分镜 · 5 先草图再整片 · 6 改片 · 五个常见毛病 · 发布前

---

## 0 准备

**先问清楚这些（一次问完，别一条条问）：**

1. **音频文件**：mp3、m4a、flac、wav 都行。QQ 音乐的 `.qmc`、网易云的 `.ncm`、Apple Music 的下载都是加密的，读不了。如果音频是从视频里取的，先用 ffprobe 看码率：标着"无损"的视频，实际可能只有 60 kbps 左右。做草图够用，正式渲染前最好换成高音质版。
2. **歌词**：LRC 或 SRT 最好（带时间轴）；纯文本也行，时间轴我们自己对。歌词有版权，由用户提供，代码读文件来显示。
3. **参考视频**（如果有）：只学风格，不搬内容。
4. **长度**：整首还是一段。建议先做 1–2 分钟。很多歌后半首是重复前半首的歌词，剪到每行都唱过一遍为止就够了。
5. **画幅**：横屏 16:9 还是竖屏 9:16。两种构图的分镜完全不一样，要先定。
6. **角色**：沿用已有的，还是新设计。

**剪音频**：切在两句之间的换气处，开头加 0.05–0.25 秒淡入；结尾留 3–6 秒淡出，给收尾镜头用。剪好先发一段试听给用户（m4a 很小，手机能收）。

```bash
ffmpeg -i 原曲.m4a -af "atrim=start=0:end=120.27,asetpts=PTS-STARTPTS,afade=t=in:st=0:d=0.05,afade=t=out:st=114.3:d=5.97" -ar 44100 -ac 2 -c:a pcm_s16le song.wav
ffmpeg -i song.wav -c:a aac -b:a 128k 试听.m4a
```

**建项目**：

```bash
python3 <skill>/scripts/new_project.py <项目文件夹> --style crayon --song song.wav --title "片名"
cd …/<项目名> && npx -y hyperframes@0.9.41 check
```

## 1 理解音乐

产出：`song.md`、`lyrics.srt`、`data/timing.json`（以及生成出来的 `src/data/timing.js`）。

1. **测节拍**：`.venv/bin/python -I <skill>/scripts/beats.py assets/song.wav --start-bpm 80`。慢歌一定要给一个大概的起始 BPM，否则容易测成两倍：实际 80 BPM 左右的歌，默认可能测出 150 多（把八分音符当成了拍）。慢歌一小节约 3 秒，常常一句一小节，很多句是弱起。脚本会按小节打印响度，副歌通常明显变响。也可以对照 `npx hyperframes audio assets/song.wav --only sections,onsets,moments --json`。
2. **歌词和时间**：`python3 <skill>/scripts/set_lyrics.py 用户给的.srt`。要把每行歌词按实际演唱拆成乐句：一行可以有两个乐句，画面上排成上下两排。拿用户给的文字和字幕逐句对一遍，有出入就问用户。（粤语歌里有些字是方言写法，照原样保留，不要擅自"纠正"。）
3. **没有时间轴时**：如果有带字幕的歌词视频，只从里面取时间。做法：用 10 fps 截下字幕那一条，亮度大于 200 的像素当作文字；相邻两帧文字区域的交并比（IoU）突然下降，就是换了一句。最后把每句的字幕截图竖着拼起来，人工核对一遍。Whisper 识别唱歌基本认不出字，别指望它。
4. **查资料**：上网搜这首歌的背景、乐评、听众的理解，归纳出 3–5 种理解，每条附来源链接。再写出自己的理解，比如歌里反复出现的意象各代表什么。
5. **写 `song.md`**：基本信息、段落表（前奏、主歌、副歌、间奏、尾奏的起止时间）、速度和小节、每句歌词的时间（只写时间和行号，不必抄整段歌词）、情绪走向（哪里最揪心，比如一句 8 秒的长音适合给近景）、几种理解。

<role>你是 MV 的音乐分析师。</role>
<task>分析 assets/song.wav 和用户给的歌词文件：测出 BPM、拍点、小节线，标出前奏、主歌、副歌、长音和淡出的时间；把歌词按演唱拆成乐句，写进 data/timing.json 和 lyrics.srt；上网找 3–5 种对这首歌的主流理解并附来源；最后整理成 song.md。</task>
<avoid>自己转写或背诵歌词；把八分音符当成拍；把不确定的时间当成确定的。</avoid>
<check>歌词文字和用户给的逐句一致；时间可疑的乐句单独列出来等用户确认。</check>

## 2 定画风

产出：`style.md`、一张样图、一段约 6 秒带音乐的样片、一张对比图。

**有参考片时**：

1. `.venv/bin/python -I <skill>/scripts/analyze_ref.py ~/Downloads/参考.mp4`：生成每 0.5 秒一帧的接触表、每秒一张原尺寸帧、BPM、切点。
2. 用 Read 逐张看接触表。转场和快切的地方再用 `contact.py` 按 0.25 秒或逐帧细看。
3. `palette.py` 给天空、草地、皮肤、头发、字等区域取色。
4. 写 `style.md`：一句话风格；测出来的数字（BPM、每秒换几张画、镜头平均几秒、暗角多深）；节奏结构（比如"慢 → 快切爆发 → 长特写 → 远景收尾"）；配色 HEX 表；角色和背景的画法；转场；画面文字（字体、颜色、出现方式、位置、大小）；后期；不要做的事；最后一节写"套到这首歌上"的设定。
5. 选一行歌词做样片：先截静帧给自己看，改到满意再渲 6 秒带音乐的样片。再拼一张对比图（旧版 / 新版 / 参考片同一段落）。

**没有参考片时**（教程的做法）：用代码按 3 种画风画同一个开场画面（比如像素风、纸艺拼贴、蜡笔手绘），各出一张 1920×1080，每张附一句为什么适合这首歌，让用户挑。已经有四套起步模板（蜡笔、纸艺、夜城流光、像素光影），可以先从这几套里各出一张；夜城流光版、像素光影版直接给 `references/style-nightcity/`、`references/style-pixel/` 里的参考图看也行。像素光影版还能用 `tools/times` 一次出同一个画面的四个时段，让用户挑钟点。

**方案光用文字说不清时，渲一张对比图**：比如纸艺版的舞台方式，A 是书一直在画面里，像看木偶戏；B 是场景铺满全屏，开头和结尾保留书（模板用的是 B）。同一个场景用两种方式各渲一帧，拼成对比图给用户看就明白了。

<role>你是视觉风格分析师兼美术指导。</role>
<task>拆解参考片的风格：每 0.5 秒一帧逐张看，测出节拍和切点，给关键区域取色，写成 style.md（一句话风格、数字、配色 HEX、角色与背景画法、切换频率与运镜、转场、字幕规则、后期、不要做的事）。然后按 style.md 用代码画一行歌词的样图和约 6 秒的样片，和参考片同一段落做对比图。</task>
<avoid>只看开头几秒；照搬参考片的角色、情节、构图；套用现成的风格模板；生图模型；深色背景配霓虹色、紫色渐变；满屏文字。</avoid>
<check>样片和参考片同段落对比，列出节奏和构图上的差距，逐条改；把所有颜色和尺寸参数记进 style.md，后面每个镜头都按它画。</check>

## 3 画角色

产出：`src/character.js`（所有镜头都从这里取角色）、角色设定图。

- **接口**：`drawPerson(ctx, who, …, pose)`。`pose` 至少包括：朝向（3/4 侧面、`flip` 镜像、背影）、表情（neutral、smile、happy、shy、sad、worry、surprise、cry）、动作（walk 走路、reach 伸手、lift 踮脚、sit 坐、promise 勾手指、拿道具，以及故事要用的特殊动作，比如弹琴、骑车）、头的角度、视线、眨眼。
- **区分两个主角**：靠发型和专属色。比如一个短发、黄衬衫，另一个长发、绿上衣配橙裙子；专属色全片不换。
- **画法规则**：Q 版的手臂要短，伸出去的手和垂下的手一样长；手肘画成经过肘部的圆弧，不能折成硬角。长发角色不画背影（头发会盖住整个身子，像鬼），转身直接镜像。道具要贴着手，不能挡住脸。
- **设定图**：`npx -y hyperframes@0.9.41 snapshot tools/sheet --at 0.5 --no-end -o renders/_sheet --timeout 120000`。图上要有各种姿势、表情表和配色。

<role>你是角色设计师。</role>
<task>按 style.md 的画法，把这支 MV 的主角写成独立模块 src/character.js：统一的绘制接口，参数是朝向、表情、动作。表情至少有开心、害羞、难过、哭、惊讶；动作至少有走、伸手、坐、拿道具，再加上故事需要的动作。输出一张设定图（各种姿势、表情表、配色），等用户确认。</task>
<avoid>每个镜头重新画一遍角色；道具和手分开；道具挡住脸；手臂太长；手肘折成硬角；长发背影。</avoid>
<check>设定图里同一个角色在每种姿势下的比例和配色一致；坐下、伸手这类姿势没有被画布的边切掉。</check>

## 4 剧本和分镜（最重要的一步）

内容归 **lyric-scene-mv** 管：故事怎么讲、每句歌词配什么画面、动作落在哪个字、两镜之间靠什么接、外壳和物件线。这一步读它、照它做，交出三份文件：

- `story.md`：人物关系、转折、回忆、颜色逻辑、母题、外壳、两条线。
- `分镜表.md`：一行歌词一行，写词眼和落点字、沾边方式、画面、动作、物件、接法。
- `逐字时间.json`：每个字在第几秒唱到（它的 `song_timing.py` 出）。

用户确认分镜之后，回到这里把它变成代码：

1. `python3 scripts/words_to_js.py 分镜/逐字时间.json`：写 `src/data/words.js`。项目音频是从整首歌中间截的一段时，加 `--offset 截取起点`。
2. 镜头里取时间，不写死秒数：

```js
import words from "../data/words.js";
import { makeCues, hit, settle, relay } from "../cues.js";
const C = makeCues(words);                         // C.at(行号, 字序)：那个字开唱的整片时间
const jump = hit(T, C.at(7, 6), { pre: 0.28 });    // 做一下就回来，顶点在字上
const up = settle(T, C.at(7, 6), { pre: 0.26 });   // 做完停住
const card = relay([[33.4, "口袋"], [34.1, "手里"]], T); // 物件接力：每个镜头只画当前状态
```

3. 分镜表里的"镜头"列对应 `SHOTS` 的一项，切点用分镜表给的秒数（`words` 里每行也有建议切点 `cut`）。
4. 例子：`references/examples/cues-crayon/`（蜡笔，动作踩字、人物挂点、游戏界面贴纸）。像素版的 `scenes/rain-hands.js` 也用 `cues.js` 取时间（没有歌词文件时，手写每句的起止和字数）。

<task>读 lyric-scene-mv，按它的方法写 story.md 和 分镜表.md，用它的 song_timing.py 出 逐字时间.json。完成后暂停，等用户确认分镜。</task>

## 5 先草图，再整片

1. 把所有镜头写成代码。写法照 `references/style-<画风>.md` 和模板里的示例镜头。
2. `npx -y hyperframes@0.9.41 check`，必须 0 个 error。
3. 每个镜头截一张动作最清楚的关键帧：`npx -y hyperframes@0.9.41 snapshot --at 5.0,12.6,… --no-end -o renders/_sb --timeout 170000`。自己先用 Read 看一遍，修掉明显的问题（人太小、表情不对、黑边、道具位置怪）。
4. `storyboard_sheet.py` 拼成分镜总览（蓝标是现在，红标是回忆或幻想），发给用户。**用户确认之前不渲整片。**
5. 渲整片（放到后台，2 分钟的片子实测 2–11 分钟）：`npx -y hyperframes@0.9.41 render --fps=30 --max-bitrate=16M --quiet -o renders/_master.mp4`。
6. `check_render.py`：查静止段、切点、每句开唱时歌词有没有出来、有没有重复帧。再用"五个常见毛病"自查一遍，并和参考片同一段落对比。
7. `deliver.sh`：换回原曲音轨、量响度、按需要压 720p 预览。发给用户时说清楚：哪些已经查过了，哪些还要用户看（比如歌词和演唱是否对齐，这个我们听不到）。
8. 写 `REVIEW.md`：做了哪些创作决定、测了什么、哪些只是看过没有测、自己觉得最弱的镜头。

<role>你是 MV 的制作人。</role>
<task>分镜已经确认。先不渲成片：为每个镜头画一张关键帧，拼成 storyboard.png 给用户检查，确认后再做完整视频。整片里每个镜头的背景、角色、道具都在同一张画布里统一绘制，跟着镜头一起动；歌词读 lyrics.srt，放在最上层，不跟镜头动；配上原曲，按分镜的画幅和帧率导出。</task>
<avoid>把背景图和单独渲的角色视频分层叠加；草图没确认就渲整片。</avoid>
<check>用 ffmpeg 抽帧，核对每句歌词出现的时间和演唱对得上；成片音轨和原曲的响度（LUFS）一致；没有静止的段落。</check>

## 6 改片

见 `review-and-delivery.md`。简单说：用户按时间点提问题 → 自己逐帧找到真正的错 → 修 → 只渲受影响的片段 → 拼确认小样（带标题卡，720p，小于 30 MB）发给用户 → 用户说"重渲整片"再出整片 → 交付。

---

## 五个常见毛病（自查和改片时对照着用）

1. **像幻灯片**：画面动得不够。每 0.5 秒抽一帧、算相邻帧差，就能找出静止的段落（`check_render.py` 会做）。让角色一直有小动作（呼吸、晃动、眨眼），镜头一直慢慢动；每句歌词安排一个清楚的主要动作，用中近景拍。
2. **运镜晃**：镜头动得太多。每个镜头只留一种慢动作：慢推、慢移，或者跟着角色。
3. **表现力不够**：情绪最强的段落换成近景或特写，光线和色调跟着情绪变（比如夜色从裂缝里漫开，眼泪慢慢变大）。
4. **道具不对**：道具要贴着手，不能挡脸，也不能飘在半空。
5. **歌词没演出来**：某句的画面看不出这句在说什么，就换一种更直观的演法。

## 发布前

- 发抖音或 B 站时，声明里选"内容由 AI 生成"。
- 封面用片子里最好看的一帧，不另外套模板。
- 标题写上歌名和画风。
